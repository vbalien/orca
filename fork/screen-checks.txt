화면 확인(--keep으로 띄운 격리 앱: 빈 임시 프로필, Orca 계정·Slack·OpenAI 연결 없음, 봇을 실행하지 않는다):
  0) 준비: 빈 프로필이라 첫 실행 안내 창이 먼저 뜬다 — "Set up later"로 닫는다. 봇 화면에서 "New bot"으로 임시 봇 fork-verify를 만들고(에이전트는 기본값, 메시지를 보내지 않는다) 그 봇의 설정 → Slack으로 간다.
     앱은 봇을 만들면 첫 턴(인사)을 자동으로 시도한다. 격리 환경에는 에이전트 CLI·로그인이 없어 실행되지 못하는 것이 정상이다
     (검증기가 이 격리 앱 자신의 에이전트 감지 — 로그인 셸 PATH까지 — 가 0개임을 미리 확인했다). 응답이 만들어지기 시작하면 확인을 멈추고 fork/verify-linux-release.sh --stop <작업 폴더>.
  1) 연결 선택에 "Use my own Slack app"(직접 만든 Slack 앱)이 있다. 그것을 누르면 대화상자가 닫힌다. 봇의 커넥터에서 Slack을
     다시 열면 내 Slack 앱 설정(토큰 칸)이 보이고, 거기에 "깨우기 전에 확인" 카드가 있다(토큰은 넣지 않는다).
     격리 환경에는 OS 키링이 없어 "토큰을 저장할 수 없다"는 빨간 안내가 뜨는 것이 정상이다.
  2) 카드의 확인 방식이 OpenAI Decisions(맨 위)이고, JSON 칸에 기본 규칙(질문 for_the_bot, 영어)이 들어 있고, "확인할 것"은 스레드 답글만 켜져 있다. 맨 끝 } 하나를 지우면 오류가 보이고 저장이 막힌다.
  3) "Insert example" → "Topic and urgency"(질문 두 개)를 넣고, rules의 두 번째 줄을 {"question": "urgency", "blockIf": {"atMost": 0.5}}로 바꿔 깨우는 규칙·막는 규칙을 하나씩 둔다. 저장한 뒤 설정을 닫았다 다시 열어 질문 두 개와 두 규칙이 그대로다. 키 칸 이름은 "OpenAI API key"다(키는 넣지 않는다).
  4) 설정 → General 맨 아래 About에 앱 버전과 포크 안내(자체 업데이트 꺼짐, "Fork releases" 링크)만 보이고, 업데이트 확인 버튼·자동 업데이트·채널 전환이 없다.
  5) 페어링 클라이언트의 게이트 API 키(서버가 필요해 따로 띄운다: 같은 패키지로 격리 `orca serve`(ORCA_SERVE_RUNTIME=electron, 버리는 키링이 있는 독립 D-Bus)와
     그 서버를 환경으로 추가한 격리 데스크톱): 서버의 봇 → Connectors → Slack → "깨우기 전에 확인"의 OpenAI API key에 시험 키를 넣고 Save key → "Saved", 입력 칸이 빈다.
     Remove → "Not saved". 서버 프로필의 bot-slack-gate-keys/openai/에 파일이 생겼다 사라진다. 명령으로 바꿔 저장하면 "Change a Slack gate command in Orca on this computer."로 거부된다.
     (Slack 카드는 Orca Cloud가 Slack 설치 상태를 답해야 보인다. 격리 환경에는 Cloud가 없으므로 그 답 하나만 클라이언트 쪽에서 대신 준다.)
